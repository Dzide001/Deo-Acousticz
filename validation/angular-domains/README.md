# Explicit angular-domain declarations — revision 1

Optional `angularDomain` metadata can now accompany each magnitude or complex response pattern
in decoded speaker JSON. Shared-core parsing, validation, per-direction assessment and reports
handle it; Android uses the existing JSON import, speaker warnings and project recovery. There is
no new declaration editor and no automatic manufacturer-data annotation.

Legacy assets remain **UNDECLARED**. Existing axes alone do not establish that their stored values
were measured rather than mirrored or upsampled. Legacy decoded JSON and asset identities remain
unchanged because absent declarations are not serialized.

## Schema

For a pattern whose stored azimuths include 0°, 5°, 10° and 350°, and elevation is 0°:

```json
{
  "angularDomain": {
    "version": 1,
    "provenance": "Describe and cite the original angular acquisition/processing",
    "regions": [
      {"origin":"MEASURED", "azimuths":[0,10], "elevations":[0], "basis":"Original acquired directions"},
      {"origin":"SYMMETRY", "azimuths":[350], "elevations":[0], "basis":"Declared left/right symmetry assumption", "operation":"MIRROR_AZIMUTH_ZERO"},
      {"origin":"INTERPOLATED", "azimuths":[5], "elevations":[0], "basis":"Interpolated from retained angular samples", "method":"DB_LINEAR_ANGULAR"}
    ]
  }
}
```

Each region selects the Cartesian product of **existing grid knots**, not a continuously measured
angular area. Unselected knots remain undeclared. Regions cannot overlap or introduce new samples.
Wrapped azimuths are normalized; duplicate aliases and selectors absent from the actual grid fail.
The schema allows at most 256 regions and one million declared-grid knots per pattern. Unknown
versions/fields, blank provenance/basis and unsupported interpolation methods are rejected.

`MIRROR_AZIMUTH_ZERO` maps `(az, el)` to `(-az, el)`; `MIRROR_ELEVATION_ZERO` maps to
`(az, -el)`. Every symmetry target must map directly to an existing knot declared MEASURED.
Missing sources, derived-only chains and cycles are rejected. The declaration records the coordinate
assumption; it does **not** copy values, test physical symmetry, authenticate acquisition, or prove
that existing amplitudes/phases were generated by the declared process.

Pre-interpolated magnitude samples declare `DB_LINEAR_ANGULAR`. Complex samples instead declare
`CARTESIAN_LINEAR_ANGULAR`; magnitude and complex grids have separate declarations. This version
records those two supported method labels rather than guessing undocumented upstream processing.
Declared origins concern angular acquisition, not whether a measured IR later underwent ordinary
windowing, frequency integration or normalization.

Declarations are immutable, persisted in the speaker asset and included in its revision/hash.
Adding a declaration deliberately creates a different decoded asset even with identical responses;
recovery still requires the exact expected revision. Existing project storage needs no migration.

## Runtime assessment and Android

`SpeakerAngularSupport.at(data, frequencyHz, azimuth, elevation, response)` assesses an **exact
stored frequency**. It returns null when that response/frequency is absent; it does not interpolate
provenance between frequencies. Its result separates:

- `origin`: stored MEASURED/SYMMETRY/INTERPOLATED/UNDECLARED origin, or runtime INTERPOLATED,
  AZIMUTH_REPLICATION or UNAVAILABLE;
- `runtimeInterpolation`: whether evaluation lies between stored knots;
- `contributors`: declared origins of the contributing stored samples;
- `samplingStatus`: the existing sparse-grid/domain diagnostic.

A stored pre-interpolated knot has origin INTERPOLATED even when runtime interpolation is false.
A between-knot prediction remains interpolated even when all its contributors were measured.
Stored-knot/pole sampling labels are now `STORED_KNOT` / `STORED_POLE`; they no longer imply
measured acquisition. Signed-zero elevation queries are handled without inventing a second node.

Angular-support report schema 2 adds declaration state, per-origin counts and canonical declarations
to every magnitude/complex band. Android's existing warning panel flags undeclared, symmetry-derived
and pre-interpolated storage. Project reports retain the same shared details. A dense stored grid
cannot suppress the warning that its added points were interpolated. Existing numerical interpolation,
missing-band/elevation behavior and prediction values remain unchanged. These are declarations,
not calibration certificates, accuracy guarantees or a new refusal policy for legacy extrapolation.

## Retained validation

The [real PRX635 benchmark](../public-measurements/README.md) is replayed without changing its
original files, holdout targets, references or thresholds. This package additionally annotates the
known training directions and creates a 5° storage grid **using training interpolation only**.
It never substitutes measured held-out levels into the source model. Added points at held-out angles
are explicitly labelled INTERPOLATED; they are not new measured evidence. Nominal survey angles
are used only for stored-node provenance checks; production receiver coordinates are not snapped.

Both annotated and upsampled variants reproduce the independent numerical reference within
0.000001 dB and retain the original failed physical screens:

| Training grid | RMS error | Maximum error | Original and 5° storage variants |
|---|---:|---:|---|
| 20° | 0.615063 dB | 2.615989 dB | FAILED |
| 10° | 0.500084 dB | 2.655764 dB | FAILED |

`recovery-fixture.json` is a separate **synthetic test-only** asset with all three declaration kinds
in magnitude and complex patterns; it is not physical evidence. Android tests cover disk save and
fresh reopen, identical declarations/warnings/hashes/levels and atomic rejection of invalid imports.
Shared tests cover partial domains, overlap, cycles, missing symmetry sources, method compatibility,
legacy behavior, knot versus runtime interpolation and stable asset serialization.

From `android/`:

```sh
./gradlew :shared-core:jvmTest --tests '*AngularDomainTest' --tests '*AngularDomainPackageTest' --tests '*PublicMeasurementComparisonTest' :app:testDebugUnitTest --tests '*AngularSupportRecoveryTest' --offline
```

Fresh results: `android/shared-core/build/reports/angular-domains/results.json`.
The focused final run passed **74 tests** (49 shared, 25 Android), Android debug assembly and iOS
simulator shared-test compilation. The original physical comparison report remains byte-for-byte
unchanged; both predeclared accuracy screens still fail.
Reviewed evidence and execution details: [results/](results/). No source-data download or new runtime
dependency is needed. On-device visual acceptance remains separate from automated checks.
