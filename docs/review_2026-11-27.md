## Corrections and qualifications

1. **Release has run on the OnePlus.** The retained
   [pressure-cache acceptance](../validation/pressure-packed-cache/README.md)
   records an R8-optimized, non-debuggable release APK signed with the development
   test key. Initial/reopen bounds were 147.8 / 152.4 s at 55.2 dB. Native compact
   inputs/DSP/assets and original-project restoration were verified. Production
   signing, distribution and broader release acceptance are still open.
2. **Current local evidence is 667 shared + 449 Android cases**, plus independent
   reference scripts and native checks, not the older commit-message count. The
   retained audit passed again during this follow-up; the entire suite was not
   rerun for YAML/docs/ref-only changes. These results do not imply GitHub passed.
3. **`refSplDb` is dormant, not an unreferenced symbol:** the disabled optimizer
   passes it to `ArrayCalcOptimizer`. `directContribution` has no callsites outside
   its definition. Its dependencies include compatibility/test adapters; remove
   the unreachable legacy route and migrate DSP tests to production shared requests
   as a separate cleanup, rather than deleting all callees indiscriminately.
4. **Threading:** the pressure conversion holds the cache lock and polls
   cancellation per at most 32 rows. Production `calculateProfiled` constructs a
   request-local field and iterates receivers sequentially. Separate requests do
   not share that lock or diagnostics. Thus shared-worker contention/counter races
   are future parallelization constraints, not an established current bottleneck.
   Use per-worker counters and merge them if this execution model changes.
5. **Performance:** bounded offset-scene gains are 7.89–8.94%; common-scene pairs
   are mixed. The full expensive offset venue and its native performance remain
   unqualified. The ~150 s native common-scene result is still unsuitable for
   interactive design. No ArrayCalc-class speed or manufacturer accuracy claim follows.
